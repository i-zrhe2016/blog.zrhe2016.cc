自己在使用codex过程中，由于前期模型能力有限，做出的产品常常不符合预期。于是自己编写了一套workflow，将需求分析，开发，测试，验证与模型编排调度集成到一起。本项目经过100+pr的迭代更新，可以稳定的实现各种需求，保证想法和做出的产品效果一致。

## Codex Development Workflow

一套面向 Codex 与 Claude Code 的多 Agent 智能软件开发工作流

GitHub：[i-zrhe2016/codex-development-workflow](https://github.com/i-zrhe2016/codex-development-workflow)

项目核心理念：让 AI 不只是编写代码，而是像成熟的软件工程团队一样，有计划、有分工、有验证地完成开发。

### 与普通 AI 编程工作流有什么不同？

1. 自适应多 Agent 协作：主 Agent 负责架构、任务拆分和调度，子 Agent 负责实现与验证。根据任务依赖、文件冲突和系统资源，动态决定并行或串行执行。

2. 独立验证机制：开发 Agent 不负责最终验收，由全新上下文的验证 Agent 独立检查，减少 AI 自己写代码、自己证明正确的问题。

3. 风险驱动的质量门禁：不仅要求测试通过，还检查测试是否真正有效，包括边界条件、异常路径、权限安全、回归风险等。

4. GitHub 原生任务管理：采用 Plan → Ticket → Branch → PR 的结构，将需求、实现、验收证据和交付过程关联起来，支持任务中断后恢复。

5. 智能上下文管理：主 Agent 保持精简，子 Agent 按需加载上下文，任务结束后保留关键证据，减少无关信息和重复 Token 消耗。

6. Skill Eval 自我改进：开发完成后评估工作流本身，通过真实任务的盲测 A/B 对比验证 Skill 改动是否有效，而不是凭主观感觉不断增加规则。

7. 分阶段交付与权限控制：规划、开发、验证、发布、合并分别管理。AI 可以完成本地开发和验证，但 Commit、Push、PR、Merge 等操作遵循用户授权边界。

```text
+------------------------------+

+--------------+---------------+
               |
     +---------+---------+---------+
     |                   |         |
+----v-----+       +-----v----+ +--v-------+
| 开发 A   |       | 开发 B   | | 开发 C   |
+----+-----+       +-----+----+ +--+-------+
     |                   |         |
     +---------+---------+---------+
               |
      [依赖允许且写入范围隔离]
               |
      +--------v---------+
      | 独立验证 Agent   |
      +--------+---------+
               |
      +--------v---------+
      | 测试质量门禁     |
      | 验收证据 · 风险检查|

      +--------+---------+
               |
      +--------v---------+

      | 工作流持续改进   |
      +------------------+

```

### 最大的差异化优势

普通 AI Coding 工具主要关注 如何更快生成代码。

Codex Development Workflow 更关注 如何通过多 Agent 协作、独立质量验证、持久化任务状态和可衡量的流程改进，让 AI 开发复杂软件变得可靠、可控、可恢复。

它的独特价值不是某一项孤立技术，而是把这些机制整合为一套完整的软件工程工作流。
