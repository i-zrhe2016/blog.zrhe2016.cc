GitHub 原生任务管理：采用 Plan → Ticket → Branch → PR 的结构，将需求、实现、验收证据和交付过程关联起来，支持任务中断后恢复。</p>\n<p>5. 智能上下文管理：主 Agent 保持精简，子 Agent 按需加载上下文，任务结束后保留关键证据，减少无关信息和重复 Token 消耗。</p>\n<p>6. Skill Eval 自我改进：开发完成后评估工作流本身，通过真实任务的盲测 A/B 对比验证 Skill 改动是否有效，而不是凭主观感觉不断增加规则。</p>\n<p>7. 分阶段交付与权限控制：规划、开发、验证、发布、合并分别管理。AI 可以完成本地开发和验证，但 Commit、Push、PR、Merge 等操作遵循用户授权边界。</p>\n<h3
